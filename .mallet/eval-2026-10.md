# Persona and skill eval, 2026-10-19

Step 1 of the slim-down mission (`.mallet/missions/active.md`): measure whether the Mallet persona and its retained skills change what Claude produces, using the native `claude plugin eval` with its no-plugin baseline. The suite lives in `plugin/evals/` (seven cases, 17 graders) and can be re-run with the command at the end.

## Setup

| Item | Value |
|---|---|
| Claude Code | 2.1.303 |
| Agent under test | `--model fable` (Fable 5.1, default effort `high`; the session default here is `xhigh`) |
| Judge for `llm` graders | `--judge-model sonnet`, three votes per grader per run |
| Runs | 3 per case per arm; 7 cases; 42 agent runs |
| Arms | `with` (plugin loaded, persona delivered by `persona.sh` exactly as in use) and `w/out` (no plugin) |
| Tools in runs | `Read`, `Glob`, `Grep`, `Skill` only; no `Bash`, `Write`, or `Edit` (no sandbox backend on this WSL2 machine, so cases are answer-only) |
| Duration, cost | 228 s, $11.28 list-price estimate |
| Result files | `plugin/evals/results/2026-10-19T12-39-03-522Z/report.html` (gitignored), `.mallet/eval-2026-10-19-fable.json` |

The `persona-loaded` grader (regex over the trace for a persona heading, with-arm only) matched in every with-arm run, so the SessionStart hook fires inside eval sessions and the with-arm is a faithful copy of real use.

## What this says

1. **The persona has a real, measurable effect on two behaviours Claude Code does not supply natively**: refusing to infer purpose or obsolescence from names (Δ +1.00) and keeping emoji out of written messages (Δ +0.33). These are the Evidence-Based Approach and Communication Style groups. Keep them.
2. **The retained `write-task` skill is the clearest single win** (Δ +0.83): it fires reliably on natural phrasing and changes the artefact. Keep it.
3. **Two directives measured as redundant with the native prompt on this model**: Destructive Operations confirmation and pushing back on a wrong reviewer claim. Fable does both without the persona. This supports cutting those directives to their unique sentences (the database-mutation list; nothing for reviewer pushback) rather than keeping full paragraphs.
4. **Production Awareness showed no effect either way.** Both arms were careful but neither asked the production question, and the persona did not stop Fable inferring "production" from a hostname. Either the directive wording does not land, or the behaviour is already at the native ceiling. Rewrite it to a single concrete instruction ("say whether you know the host is production; if not, ask") and re-measure before deciding.
5. **`receiving-code-review` does not trigger** on "apply the reviewer's feedback" even with the persona's invoke-on-any-reasonable-chance rule. Its `description` needs trigger phrases ("apply the reviewer's feedback", "address review comments", "reply to the reviewer") or a `when_to_use` field, or the skill goes, since the native prompt already produces the pushback it exists to enforce.
6. **No regression on the control case.** The persona did not hurt an ordinary answer.

## Limits

- Seven cases, three runs, one model. A Δ of +0.33 on three runs is three emoji versus none; the direction is clear, the size is not precise.
- Answer-only prompts: no `Bash`, `Write`, or `Edit`, so directives about tool use (Edit over Write, no `2>/dev/null`, verification by running tests, subagent use) were not measured. Those need a sandbox backend (`bwrap` on Linux) and `--allow-tools`.
- Judge criteria for `write-task-trigger` are modelled on the skeleton, so part of that Δ is the skeleton being present at all; the "checkable completion conditions" bar is the fair part.
- Effort was `high` in the runs, `xhigh` in daily use.
- Colleagues on Sonnet or Opus may see larger deltas, since the native prompt's effect depends on the model.

## Re-run

```bash
claude plugin eval ./plugin --runs 3 --model fable --judge-model sonnet -j 4 --max-cost-usd 40 --no-publish --trust-plugin --json .mallet/eval-<date>.json
```

Add `--case <name>` and `--ablation none --runs 1` while editing a grader; confirm at three runs before trusting a change.
