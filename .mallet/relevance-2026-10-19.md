# Mallet relevance assessment, 2026-10-19

Scope: every shipped component of the `mallet` plugin at the local checkout `8534417` (master, 2026-10-08). The remote `master` is two commits ahead at `be2eaa9` (2026-10-15, PR #31 from a colleague: a CRLF fix to the Windows transition touching `.claude/install-payload.sh`, `tests/test-17-transition.sh`, and `CHANGELOG.md`); they were fetched and read for this report, change nothing in the component table, and are counted in the git statistics. Judged against Claude Code 2.1.303 (the version installed here), the official docs at code.claude.com, the Claude Code changelog, the official plugin marketplace, and the wider ecosystem. Analysis only: nothing was edited, committed, or fixed. The project `self-assessment` skill's review and fix phases were not run; its "verify before reporting" rule was applied to every claim below.

Evidence conventions: `file:line` references are to this repo. Native claims cite a docs page (`code.claude.com/docs/en/<page>`), a changelog version (`github.com/anthropics/claude-code/blob/main/CHANGELOG.md`), the official marketplace, or the Claude Code 2.1.303 system prompt as delivered to this session, which is not published at a URL and is marked "system prompt (observed)" where used. Every number in the cost section was measured in this session; the commands are in the appendix.

---

## Verdict

**Slim down to a core.** Mallet's distribution mechanism (one plugin, every project, central updates) is still the right one, and a handful of its pieces are genuinely unique and in use: the evidence-first persona, `write-task`, `next-steps`, `create-pr`'s PR summary, `receiving-code-review`, `reviewing-sessions`, `council`, and the `code-reviewer` agent. Almost everything else has been absorbed by Claude Code since February: auto memory replaced the memory directives, `/rewind` (alias `/checkpoint`) and session recaps cover checkpoints, `/autocompact <tokens>` replaces session-watch, the auto-mode classifier covers the command guard's list, LSP plugins replace the typecheck hook, `/init` plus `/doctor` plus the official `claude-code-setup` plugin replace `discover`, native plan mode and ultracode cover most of `plan-feature` and the feature pipeline, and `.claude/rules/` plus `.claude/skills/` make `.mallet/conventions.md` and `.mallet/skills/` a second, weaker instruction system that the native tooling does not know about. The measured cost of carrying all of it is 5,006 input tokens on every request (24% on top of a bare session) and, since September, about three quarters of the commits going to harness-tracking and transition work rather than user value. Retiring Mallet outright would lose the unique skills and the shared persona for a small saving; keeping it as is means paying maintenance for duplicated infrastructure. Confidence: high on the infrastructure verdicts, medium on the skill verdicts (usage evidence is one machine, 30 days). What would change this: an eval (`claude plugin eval`, native since 2.1.269) showing the persona measurably improves outcomes, or colleagues' usage data showing the pipeline or `discover` in regular use.

## 2. The whole beyond the parts

**What the combination buys.** A plugin is the native way to give every project on a machine, and every colleague who installs it, one persona, one set of skills and agents, and central updates (code.claude.com/docs/en/plugins/overview). A plain `CLAUDE.md` cannot do that: a user-level `~/.claude/CLAUDE.md` is per machine and hand-copied, a project `CLAUDE.md` is per repository. The pre-plugin Mallet was exactly the hand-copied variant, and the move to a plugin on 2026-09-28 was the right call. The packaging is not the problem.

**What it does not buy.** The combination argument holds for the persona plus a few opinionated skills. It does not hold for the hooks, the statusline plumbing, the project-skill and conventions directories, or the pipeline: each of those is now a parallel implementation of something Claude Code ships, and parallel implementations have a cost beyond tokens. Two concrete cases: `.mallet/conventions.md` is lost after compaction where `CLAUDE.md` is re-read, and `.mallet/skills/` skills are invisible to the `/` menu, `/skill-doctor`, hot reload, and cloud sessions where `.claude/skills/` skills are not. A team member who learns Mallet's way learns a weaker version of the native way.

**Reach.** Plugins enabled in user settings do not load in cloud sessions, routines, or Cowork (code.claude.com/docs/en/plugins/overview: "A cloud session… doesn't load the plugins in your local settings"; skills, "Skills in Cowork and cloud sessions"). A committed project `CLAUDE.md`, `.claude/rules/`, and `.claude/skills/` do. For team-shared conventions the native, committed form now reaches more surfaces than the plugin.

**Could CLAUDE.md, settings, and a few skills reproduce the core today, and at what cost?** Yes, for the persona and conventions: a user-level `CLAUDE.md` or an output style, plus committed `.claude/rules/` per repo, reproduce the directives with no hooks and no tests. The cost is distribution: each colleague installs or copies once and updates by hand, and the persona cannot be versioned centrally. That is precisely the cost a slimmed plugin removes, which is why the recommendation is to keep the plugin and change what is in it, not to go back to files. The remaining unique skills (`write-task`, `next-steps`, `receiving-code-review`, `reviewing-sessions`, `create-pr`, `council`, `adr`) and the `code-reviewer` agent are ordinary plugin content with no infrastructure behind them; they cost their descriptions when idle (3,297 characters for all 17 skills today) and nothing else.

**The unmeasured assumption.** Everything above assumes the persona changes behaviour. No eval has ever been run. `claude plugin eval` (changelog 2.1.269) and the `skill-creator` eval modes exist for exactly this. Until there is a number, "evidence-first discipline" is a belief about the persona, not evidence. Confidence that the persona helps: medium, from reading it against the native prompt; confidence that it is worth 3,109 tokens per request: unknown.
